# English Wrong-Question Manager · Design Spec

**Date:** 2026-04-01
**Status:** Approved

---

## 1. Overview

A web-based English wrong-question management and adaptive practice system.

**Core loop:** Import docx questions → random quiz → wrong answer → AI analysis → user confirmation → similar questions practice (举一反三) → permanent record.

---

## 2. Technical Stack

| Layer | Technology | Notes |
|-------|-----------|-------|
| Frontend | React + Vite | Component-based, state-managed; UI extensible for multi-user |
| Backend | FastAPI (Python) | REST API, SQLite local DB; Auth layer extensible for multi-user |
| AI | Cloud API (OpenAI/Claude) | All AI tasks: docx parsing, wrong-answer analysis, similar question generation |

**Architecture:** Frontend-backend separation. Local SQLite storage, designed to add Auth layer for multi-user in the future.

---

## 3. Data Model

### Question
```python
id: int (PK)
content: str          # question text
options: dict         # {"A": "...", "B": "...", "C": "...", "D": "..."}
answer: str           # "A" | "B" | "C" | "D"
docx_filename: str    # source file for reference
created_at: datetime
```

### Tag
```python
id: int (PK)
name: str             # e.g. "#subjunctive-mood", "#inversion", "#past-perfect"
created_by_ai: bool   # always True in this design
```

### QuestionTag (M2M)
```python
question_id: int (FK)
tag_id: int (FK)
```

### WrongQuestion
```python
id: int (PK)
question_id: int (FK)
user_id: int | None      # nullable for single-user; extend to FK when multi-user
wrong_count: int         # how many times answered wrong
consecutive_correct: int # resets to 0 on wrong; reaches 3 → status = "mastered"
last_wrong_at: datetime
status: str              # "pending_review" | "confirmed" | "mastered"
```

### AIAnalysis
```python
id: int (PK)
wrong_question_id: int (FK)
analysis: str         # AI-generated wrong-answer cause analysis
suggested_tags: list[str]  # AI-suggested tag names
confirmed: bool       # False = awaiting user confirmation before 举一反三
created_at: datetime
```

## 4. Key Modules

### 4.1 Docx Parser
- **Input:** User uploads a `.docx` file via web UI
- **Process:** Send docx content (extracted as text) to AI API; AI returns structured question objects
- **Output:** `Question` records inserted into SQLite
- **Prompt design:** AI receives raw docx text, outputs JSON array of `{content, options, answer, explanation}`

### 4.2 Quiz Engine
- **Question selection:** Random pick from all confirmed questions (avoid questions answered correctly recently)
- **Answer submission:** POST `/api/quiz/answer` with `{question_id, selected_answer}`
- **Correct:** Continue to next question
- **Wrong:** Create `WrongQuestion` record (status=pending_review), trigger AI analysis

### 4.3 AI Analysis (Wrong-Answer)
- Triggered automatically on wrong answer
- AI receives: question content + user's wrong answer + correct answer
- AI outputs: `{analysis: str, suggested_tags: list[str]}`
- Saved as `AIAnalysis` with `confirmed=False`
- **Semi-automatic:** Frontend displays analysis to user; user clicks "Confirm" to proceed

### 4.4 举一反三 (Similar Question Finder)
- **Triggered:** After user confirms AI analysis
- **Tag matching:** Find questions sharing **at least one tag** with the wrong question (exclude the wrong question itself). If multiple candidates exist, shuffle and pick 2–3 at random.
- **Count:** Show 2–3 similar questions
- **Fallback:** If tag match yields <2 questions, call AI API to generate new questions matching the same tags; insert generated questions into DB with source="ai_generated"
- **Practice:** User answers similar questions in sequence; same wrong-answer loop applies

### 4.5 Knowledge Tag System
- Tags are **auto-generated by AI** when analyzing wrong questions
- Tags are **not pre-defined**; the system builds its tag vocabulary organically
- Tag names use `#kebab-case` format (e.g., `#past-perfect`, `#relative-clause`)

## 5. API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/questions/import` | Upload docx, trigger AI parsing, return imported count |
| GET | `/api/questions` | List all questions (paginated) |
| POST | `/api/quiz/next` | Get next random quiz question |
| POST | `/api/quiz/answer` | Submit answer, returns correct/wrong + AI analysis if wrong |
| POST | `/api/analysis/:id/confirm` | Confirm AI analysis, trigger 举一反三 |
| GET | `/api/similar/:question_id` | Get 2–3 similar questions by tag match |
| GET | `/api/wrong-questions` | List all wrong questions |
| GET | `/api/tags` | List all tags |

## 6. Frontend Pages

1. **Upload** — Drag & drop or file picker for docx upload
2. **Question Bank** — View all imported questions with tags and status
3. **Quiz** — Single-question card with A/B/C/D options; submit button
4. **Analysis Review** — Shows AI analysis of wrong answer; Confirm / Edit / Skip buttons
5. **举一反三 Practice** — Shows 2–3 similar questions sequentially after confirmation
6. **Wrong Question Log** — History of all wrong answers with repeat-count and status

---

## 7. Design Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | Docx free-format + AI parsing | Zero template constraint on question format |
| 2 | Tag matching (not vector similarity) | Transparent and explainable; better for unstructured docx content |
| 3 | Semi-automatic (user confirms before 举一反三) | Keeps user in control; prevents AI errors from cascading |
| 4 | 2–3 similar questions per 举一反三 | Lightweight per-session; repeated small practice > one large session |
| 5 | Single-user SQLite, multi-user extensible | Simple now, upgrade path clear |

---

## 8. Additional Decisions

| # | Decision | Detail |
|---|----------|--------|
| 6 | Question type: MCQ only (v1) | Only multiple-choice (A/B/C/D) supported. AI skips non-MCQ questions during docx parsing and reports them as skipped. |
| 7 | API Key: local `.env` file | Backend reads `OPENAI_API_KEY` / `CLAUDE_API_KEY` from a `.env` file at project root. Not stored in DB. |
| 8 | "Mastered" criteria: 3 consecutive correct | A wrong question's status changes from `confirmed` → `mastered` after the user answers it correctly 3 times in a row. Requires adding `consecutive_correct: int` field to `WrongQuestion`. |
| 9 | Quiz session: 10 questions per session | Each quiz is a fixed session of 10 questions. On completion, show a session summary (score, wrong questions, tags). |
| 10 | Tag normalization: auto lowercase-kebab-case | Before saving any AI-generated tag, backend normalizes to lowercase kebab-case (e.g. `PastPerfect` → `past-perfect`). Prevents duplicate tags from AI output variation. |

---

## 9. Out of Scope (v1)

- Multi-user auth (add later)
- Spaced repetition scheduling (add later with a review queue)
- Non-MCQ question types (fill-in-blank, essay, etc.)
- Manual question entry (docx import only)
- Question editing / deletion
- Export wrong-question reports
